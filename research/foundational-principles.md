# Foundational Research Principles

This document captures the project's scientific orientation, biological framing, and mathematical aspirations. It is a research compass for agents and contributors, not a rigid implementation contract. Use it to shape hypotheses, experiments, and design discussions; when an implementation departs from a principle, describe the departure and its evidence rather than silently treating the principle as already satisfied.

## 1. Animal learning as a scientific reference

The project aims to investigate adaptive mechanisms inspired by animal learning, not merely to maximize scores with task-specific heuristics or conventional tabular reinforcement learning. The following are working theoretical commitments, informed by classical learning theory; they are hypotheses to operationalize and test, not claims that the current code already implements them fully.

1. **Informative prediction (Rescorla–Wagner intuition).** Association should depend on how much a cue changes expectation beyond the background rate, rather than raw co-occurrence alone. Repeated uninformative noise should lose influence through habituation or competition with a learned baseline.
2. **Economy of explanation (blocking and parsimony).** Do not favor a compound association merely because several cues co-occur. Prefer a simpler predictor when it already explains the outcome; add compound structure when simpler predictors systematically leave prediction error.
3. **Conditional inhibition (Pavlovian inhibition).** A cancellation or safety cue should learn a context-dependent inhibitory relation that suppresses an expectation while preserving the underlying excitatory association. Reversal should be measured as new learning and competition, not assumed to require erasing history.
4. **Temporal traces and expectation discharge.** A cue may leave a decaying, time-sensitive trace that bridges delays. When an expected event occurs, that particular expectation should be consumed or discharged so that a sustained cue does not repeatedly predict the same one-off outcome.
5. **Novelty-driven orienting.** Exploration should be attracted by local uncertainty or unfamiliarity, rather than being only random action selection or a clock measured from birth. Evidence of danger should rapidly reduce selection of a route; evidence of success should reinforce it.

For each principle, define observable predictions and discriminating tests. Keep alternative explanations in view: a benchmark pass alone does not establish the biological mechanism.

## 2. Universality and despecialization

The intended agent should not need semantic labels such as “food,” “room,” “grid,” “signal,” or “noise” in its learning architecture.

- **Semantic blindness:** sensory channels are anonymous activity inputs. The task may assign meaning to channels, but the learner should not branch on those meanings.
- **Parity of channels:** sensory, internally generated motor, and wellbeing/value activity should participate in a common representational and learning framework, with equivalent trace and association rules where the theory calls for them.
- **Action as an internal event:** candidate motor activity is generated by the agent and used as a predictor of subsequent input changes, not supplied as an environmental observation.
- **Permutation invariance:** consistent relabeling of sensor and action channels should preserve the corresponding learned behavior and predictions. Test this by applying random permutations and mapping outputs back, not by inspecting only a canonical wiring.

The development prototype partially pursues index-agnostic features, but still has explicit node ranges and a designated value node. Treat full channel parity and invariance as targets to measure, not as established properties.

## 3. Architectural unity: avoid “walking castles”

Complex behavior should arise from a coherent learned relational structure rather than a growing collection of task-specific exceptions.

- **One source of learned causal memory is the goal.** Ask whether state, action-value, context, novelty, or replay side tables can be represented as interpretable graph relations. Do not claim the prototype already meets this ideal: `BlindGateGraphBrain` currently also maintains traces, base-rate estimates, compatibility projections, and value statistics/tables.
- **Decision by prediction is the goal.** Candidate motor events should be evaluated by propagating their consequences through learned relations toward wellbeing `W`, rather than by a task-specific action lookup.
- **Make exceptions visible.** If a side structure is retained for efficiency, compatibility, or a research experiment, document its role, its independent information content, and how it could be tested or removed. Avoid hidden sensor-index rules and scenario-specific conditionals.

These are architectural criteria for evaluating future designs, not a ban on all auxiliary data structures at the current prototype stage.

## 4. Mathematical closure and locality

- **Bounded quantities:** activations, traces, association strengths, expectations, and wellbeing are intended to remain in `[0, 1]` and use closed operations. The current `development/ops.py` exposes complement `N`, saturating addition `A`, multiplication `M`, and bounded difference `D`, plus helpers. Tests and derivations should make domain assumptions explicit.
- **Local learning:** an association should update from activity at its antecedents, its target, and explicitly defined local reference statistics. Avoid global graph-wide gradient optimization or matrix inversion as the learning explanation. Local indexes or caches may be implementation accelerators, but should not secretly change the learning rule.
- **Interpretable quantities:** name each variable by its intended meaning—e.g. event frequency, conditional expectation, evidence strength, trace intensity, or inhibition—and state what data update it. Distinguish probability-like estimates from confidence/strength; do not conflate them.
- **No unexplained constants:** every threshold, decay, learning rate, and horizon is a hypothesis or engineering parameter. Record its units/interpretation, sensitivity, and whether it is shared across environments. A fitted parameter is not inherently invalid, but test-specific unexplained tuning is weak evidence.

## 5. Minimal functional capabilities

The following five capabilities describe a proposed functional basis for adaptive behavior. They are capabilities, not a claim that exactly five Python functions or the current implementation already realizes them.

1. **AND — conjunction:** bind a combination of conditions when its joint predictive information exceeds what its parts explain individually.
2. **NOT — conditional inhibition:** suppress an expectation in the presence of a learned blocker without deleting the underlying positive association.
3. **OR — convergence/generalization:** allow distinct contexts or routes to support a shared predicted consequence or value.
4. **TIME — trace cascade:** preserve a graded, decaying record across variable delays and use its age to shape prediction.
5. **VALUE CHAIN — secondary reinforcement:** transmit value through intermediate predicted events so behavior can tolerate immediate cost in pursuit of later wellbeing.

Each capability should have a minimal, isolated benchmark, a negative control, and tests under channel permutation. The mathematical primitive set (`N`, `A`, `M`, `D`) and this functional list are different levels of description; do not equate them without a derivation.

## 6. Scientific honesty and falsification

Tests and environments should challenge the theory, not decorate it with green checks.

- A failing test is evidence of a limitation, a flawed hypothesis, an implementation defect, or a measurement problem. Diagnose which; do not conceal it.
- Do not add rules for known indices, fixed scenarios, or test-specific action sequences merely to pass a benchmark.
- Prefer a reproducible red test that identifies the model's boundary to a green result purchased with an unprincipled patch.
- Separate structural checks, controlled learning checks, and end-to-end behavior. A structural inspection is not proof of robust behavior; a behavioral pass is not proof of biological validity.
- Record seeds, permutations, environment parameters, metrics, and known failures. Report aggregate and per-seed results where stochasticity matters.

## Agent use

When proposing research or code, an agent can use this document as a checklist: identify the principle being addressed, state a falsifiable prediction, choose a discriminating experiment, note conflicts with current architecture, and report both positive and negative results. These are prompts for disciplined reasoning, not mandatory boilerplate for every edit.
